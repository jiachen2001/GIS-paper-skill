# 空间机器学习与验证设计

本文件用于带有地理位置、区域、轨迹、邻近关系或时空依赖的机器学习研究，重点防止随机划分造成空间泄漏和性能高估。

## 1. 首先定义泛化目标

模型验证方式必须服务于真实使用场景。先判断模型未来要泛化到：

- 同一区域中的新样本；
- 新街区、新城市或新区域；
- 未来时间段；
- 新个体或新路线；
- 同时新的区域与时间。

不同泛化目标需要不同数据切分。

## 2. 随机划分何时可能失效

如果相邻样本共享环境、POI、路网、遥感纹理、行政属性、重复观测或上游数据，随机 K 折可能让高度相似的观测同时进入训练和验证集，从而高估泛化性能。

不得仅因随机交叉验证分数更高就优先采用。

## 3. 可选验证策略

根据研究结构考虑：

- spatial block cross-validation；
- leave-location-out；
- leave-region-out / leave-city-out；
- group K-fold；
- leave-one-subject/route-out；
- temporal split；
- spatiotemporal split。

这些方法不是越严格越好，而要与目标部署场景匹配。

## 4. 空间 block 的设计

- block 尺度应大于主要空间相关范围或与实际泛化单元一致。
- block 太小仍可能泄漏；太大则可能造成训练样本过少和高方差。
- 可通过空间自相关范围、领域机制或多尺度敏感性分析确定合理尺度。
- 报告 block 构造方式、数量、每折样本量和空间覆盖。

## 5. 预处理泄漏

以下操作原则上只能在训练折中拟合：

- 标准化与归一化；
- 缺失值插补参数；
- PCA 与其他降维；
- 特征选择；
- 目标编码；
- 数据驱动阈值选择；
- 聚类中心或字典学习；
- 超参数搜索。

如果空间特征本身由全体样本构造，例如邻域统计、核密度、目标邻近均值，还要检查特征生成阶段是否已经泄漏验证集信息。

## 6. 空间特征与目标泄漏

重点检查：

- 使用目标变量本身或其空间平滑版本构造输入；
- 通过邻居标签、区域均值、后验统计产生特征；
- 同一地点或同一路线的重复样本跨训练与验证集；
- 图像切片相互重叠或来自同一原始大图却被随机拆分；
- embedding 来自包含测试标签或目标信息的监督流程。

## 7. 模型比较

比较模型时必须使用同一验证框架、同一折、同一评价指标。

报告：

- 各折性能；
- 平均性能与离散程度；
- 不同空间划分方案下的性能变化；
- 随机 CV 与空间 CV 的差异（如两者均有研究价值）；
- 相比简单基线的增益。

如果随机 CV 明显优于空间 CV，应优先解释为潜在空间依赖或泄漏，而不是简单认为空间 CV “太严格”。

## 8. 评价指标

指标必须与任务目标匹配：

- 连续预测：MAE、RMSE、R²、相关系数等各自含义不同；
- 分类：accuracy 在类别不平衡时可能误导，应根据任务考虑 balanced accuracy、F1、AUROC、AUPRC 等；
- 排序或评分一致性任务可考虑 Spearman、Kendall 或一致性指标。

不得只报告一个最有利指标。

## 9. 最终结论边界

如果验证只覆盖同一区域随机新样本，不能宣称模型具有跨城市或跨区域泛化能力。

如果只有空间外推验证，没有未来时间验证，也不能自动宣称时间稳定性。

验证设计决定结论边界。
